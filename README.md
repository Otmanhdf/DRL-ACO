# DRL-ACO: Deep Reinforcement Learning versus Offline Tuning for Parameter Control of Ant Colony Optimization in Weighted Multi-Objective Cloud Task Scheduling

Code, benchmark instances, trained policies and raw results for the paper

> Z. Benlalia, O. Houdaif, T. Mzili. *Deep Reinforcement Learning versus Offline Tuning for Parameter Control of Ant Colony Optimization in Weighted Multi-Objective Cloud Task Scheduling.* Soft Computing (under revision).

Every number, table and figure in the paper is computed from the CSV files in `results/` by the scripts in `src/`. The whole pipeline is deterministic (fixed seeds), and `python src/verify.py` re-runs a subset and checks it against the shipped results bit for bit.

## Contents

```
src/            source code (Python, numpy + numba)
data/           the benchmark instances (test and validation), see below
policies/       trained DQN policies (.npz weights + .json settings)
results/        raw per-run results, tuning grids, training logs
tables/         generated tables (Markdown + CSV, incl. Supplementary Table S1)
figures/        generated figures (as in the paper)
reproduce.sh    full pipeline from scratch
```

| File | Content |
| --- | --- |
| `src/core.py` | Instance generator, objectives M/E/C/LB and composite F, normalisation bounds, FCFS, Min-Min, local search, MAX–MIN ACO block |
| `src/agent.py` | MDP (17 state features, 80 actions, reward), numpy DQN, controllers: fixed, random, DQN, DQN-once |
| `src/baselines.py` | Memetic GA, memetic PSO, NSGA-II, DRL-only dispatcher |
| `src/tune.py` | Exhaustive tuning of Fixed-ACO over the 80 (α, β, ρ) actions on validation instances |
| `src/train.py` | DQN training (main policy, 5 seeds, and ablation variants) |
| `src/evaluate.py` | Paired evaluation on the 30 test instances (`main`, `ablation`, `weights`; `--workload heavy`) |
| `src/front.py` | Weight sweep of DRL-ACO vs NSGA-II and hypervolume |
| `src/worked_example.py` | Small worked example of the appendix (6 tasks, 3 VMs) |
| `src/analyze.py`, `src/tables.py` | Wilcoxon + Holm, Vargha–Delaney A12, Hodges–Lehmann CI, Friedman ranks; paper tables |
| `src/make_figures.py`, `src/figures_extra.py`, `src/fig1_flow.py` | Figures |
| `src/export_dataset.py` | Writes / checks the instances in `data/` |
| `src/verify.py` | Quick reproducibility check (~1 min) |

## Installation

Python ≥ 3.10.


## Quick start

```bash
python src/verify.py                    # checks data/ and re-runs 24 runs (~1 min)
python src/evaluate.py main 100 --reps 5  # 12 methods on five 100-task instances
```

Use an instance from the dataset in your own code:

```python
import sys; sys.path.insert(0, "src")
import numpy as np
from export_dataset import load_instance
from core import evaluate, min_min

inst = load_instance("data/test_uniform_1000.npz", rep=0)   # 1,000 tasks, 50 VMs
sigma = min_min(inst["ET"], inst["m"])                      # task -> VM assignment
print(evaluate(sigma, inst, np.full(4, 0.25)))               # M, E, C, LB, F (equal weights)
```

## Dataset (`data/`)

Synthetic instances of independent tasks on heterogeneous VMs (inconsistent ETC model). Each instance is generated by `core.make_instance(n, m, seed, workload)`; the files hold the generated values so they can be used without this code.

| Tasks n | VMs m | Test (uniform) | Test (heavy-tailed) | Validation |
| --- | --- | --- | --- | --- |
| 100 | 10 | 30 | – | 5 |
| 300 | 20 | 30 | 30 | 5 |
| 500 | 30 | 30 | – | 5 |
| 700 | 40 | 30 | – | 5 |
| 1000 | 50 | 30 | 30 | 5 |

Model:

- task length L_i ~ U[1000, 20000] MI (uniform), or a 70/25/5 % mix of log-normal short/medium/very long tasks (heavy-tailed, clipped to [500, 300000] MI);
- VM capacity MIPS_j ~ U[500, 2000]; busy power P_j = 60 + 0.08·MIPS_j W; idle power 0.6·P_j; price c_j = 1e-4·(MIPS_j/1000)² USD/s;
- affinity h_ij ~ U[0.6, 1.4]; execution time ET_ij = L_i / MIPS_j · h_ij s.

Each `data/<split>_<workload>_<n>.npz` contains, for the R instances of that group: `seed (R)`, `L (R,n)`, `mips (R,m)`, `P (R,m)`, `Pidle (R,m)`, `price (R,m)`, `h (R,n,m)` and `bounds (R,8)` = [M_lo, M_hi, E_lo, E_hi, C_lo, C_hi, LB_lo, LB_hi] (normalisation bounds of F; energy in kWh). `data/instances_index.csv` lists every instance and its seed, and `data/example_csv/` gives the first 100-task test instance as plain CSV files.

Seeds: test instance r of size n uses 30000 + 100·n + r (heavy-tailed: +500000); validation k uses 20000 + 10·n + k; training episode e of training seed s uses 10000 + 1000·s + e; every stochastic method uses run seed 7000 + r on test instance r.

## Results (`results/`)

| File | Paper |
| --- | --- |
| `main_uniform_{100,300,500,700,1000}.csv` | Tables of M, E, C, LB, F, win/tie/loss, pairwise tests, runtime; Figs. 3–6, 8 |
| `main_heavy_{300,1000}.csv` | Heavy-tailed workload table |
| `ablation_uniform_{100,1000}.csv` | Ablation table, Fig. 9 |
| `weights_uniform_300.csv` | Weight-sensitivity table (15 instances × weight vectors) |
| `front_300.csv`, `front_300_*.npz` | Hypervolume comparison with NSGA-II, Fig. 10 |
| `tune_*.csv` | Tuning grid (80 actions × 5 validation instances), Fig. 2 |
| `trainlog_*.csv` | Training curves, Fig. 11 |
| `ct_*.npz` | Per-VM completion times, Fig. 7 |
| `worked_example.json` | Worked example (appendix) |

CSV columns: `mode, workload, scale, vms, rep, weights, method, M` (s)`, E` (kWh)`, C` (USD per task)`, LB` (coefficient of variation of VM completion times)`, F` (composite objective, lower is better)`, time_s`.

Composite F at a glance (mean over 30 instances; full tables in `tables/`):

| Method | 100 | 300 | 500 | 700 | 1000 |
| --- | --- | --- | --- | --- | --- |
| Min-Min + LS | 0.1115 | 0.0970 | 0.0925 | 0.0910 | 0.0893 |
| Memetic GA | 0.1085 | 0.0965 | 0.0922 | 0.0906 | 0.0890 |
| Fixed-ACO (tuned) | 0.1078 | 0.0956 | 0.0916 | 0.0899 | 0.0887 |
| DQN-once | 0.1082 | 0.0963 | 0.0915 | 0.0899 | 0.0886 |
| DRL-ACO | 0.1073 | 0.0959 | 0.0917 | 0.0903 | 0.0887 |

As discussed in the paper, DRL-ACO clearly beats the heuristic and metaheuristic baselines and the default-parameter ACO, but is statistically tied with an ACO whose fixed parameters were tuned offline at each scale.

## Reproducing everything

```bash
bash reproduce.sh      # roughly 8-10 h on 2 cores
```

To rebuild only the statistics, tables and figures from the shipped results:

```bash
python src/analyze.py && python src/tables.py && python src/make_figures.py && python src/fig1_flow.py
```

All scripts are run from the repository root.
